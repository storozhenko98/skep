THE PREMISE

Your laptop should feel local.
Your compute does not have to be.

Skep treats your Mac and your Linux VMs as one pool of isolated development capacity. The interface stays the same whether a workspace is running three feet away or behind Google Cloud IAP.

ONE REPEATABLE LOOP

From clean image to working machine.

  1. 01

    Build

    Start an editable microVM from an OCI image. Install your tools through a full terminal and keep the builder around.

  2. 02

    Publish

    Capture a verified, immutable template. The source builder remains available when you need to change the baseline.

  3. 03

    Launch

    Create isolated, persistent workspaces with dedicated filesystems and Docker data disks. Stop them without losing state.

ONE APP, TWO EXECUTION MODES

Local when you want it.
Remote when you need it.

A / LOCAL

This Mac

Run Linux microVMs through the native Apple Silicon Microsandbox runtime. No SSH, cloud account, or administrator install.

  • Private Unix control socket
  • User-owned local service
  • Automatic helper alignment

B / REMOTE

Your Linux host

Connect using credentials already configured on your Mac. Skep supports regular SSH and Google Cloud IAP tunnels.

  • No daemon port exposed
  • Checksummed host payload
  • Automatic service updates

BOUNDARIES, NOT BRANDING

Understand what runs where.

Skep is intentionally explicit about the trust boundary. The Mac app orchestrates; the host service owns the privileged runtime; every workspace is a microVM.

01

Your private SSH keys and Google Cloud credentials stay on your Mac.

02

The remote service is reached through SSH and a host-local Unix socket—not a public API port.

03

Host binaries ship with the app, are checksum-verified, and update without deleting workspace state.

04

Docker runs inside each Linux workspace instead of sharing your Mac’s Docker daemon.

QUESTIONS

The short answers.

Is Skep open source?

Not yet. The current beta is distributed as a binary while the product and release model settle. The underlying Microsandbox runtime is Apache-2.0 software.

Does it replace Docker?

No. Skep creates the isolated Linux machines. Docker runs normally inside each builder and workspace.

Does Skep create cloud VMs?

Not in this preview. Point it at a compatible Linux VM you already control. It can parse a complete gcloud compute ssh … --tunnel-through-iap command for you.

What happens to my data when Skep updates?

The Mac app replaces matching control binaries and restarts the service. Builders, templates, workspace disks, Docker data, and exports remain on the selected host.

Why does the remote VM need KVM?

Skep runs a microVM runtime inside that host. Cloud VMs therefore need nested virtualization enabled and must expose /dev/kvm to the guest.
